# CLAUDE.md — операционная памятка

> Читать в начале каждой сессии. Это приоритетные правила, важнее поведения по умолчанию.

## Приоритет
**Критичность > скорость > простота.** Медленно и верно лучше, чем быстро с ошибкой. Всё проверять перед выдачей. Быть дотошным.

## Жёсткие ограничители (guardrails)

### Честность и точность
- Любое число — пересчитывать; итоги должны сходиться. Факты — со ссылкой; неподтверждённое помечать, не выдавать за факт. Не выдумывать названия/ссылки/цифры → «не найдено / нужно уточнить». Неуверенность помечать явно.
- Видишь ошибку/слабое место → предлагай решение, аналитично. Спорное — оспаривать аргументами, даже если идея пользователя.
- Немецкая грамматика (род, формы, Perfekt) — проверять; неуверенное помечать.
- Общение — по-русски. Любой контент (тексты/слова/переводы) — сначала по-русски на утверждение, немецкий после «ок».

### 🔴 Правило о правилах (мета, главное)
Записал правило → сразу спроси «**как это поймает машина?**». Правило, живущее только в тексте, НЕ исполняется (проверено: «speak() запрещён» записано 09.07 → нарушено 16.07; правило рода в 3 местах → нарушено 3 раза). Нельзя проверить → убрать саму возможность ошибки (генератор/шаблон); можно → сделать проверку и внести в чек-лист ниже.

### 🔴 Род и линза (ядро метода)
В тексте героя — **только его род**: der→Otto, die→Грета, das→Тео. Чужой род = ОБУЧЕНИЕ ОШИБКЕ — убрать / синоним своего рода / отдать герою того рода. Линза = ключ извлечения (цена→Отто, цвет→Грета, материал→Тео; docs/17 §0); в ЛЕКСИЧЕСКИХ темах её гипертрофировать, в ГЛАГОЛЬНЫХ блоках — не выпячивать (там учим глаголы). Писать любой текст — по `docs/17` (история-не-список, полнота слов+фраз, объём, уровень по уроку, «сериал движется»). ⚠️ Машина не проверит «прожито или названо» — тесты docs/17 §0б (вычёркивания/анонимности/«ну и что?») прогонять глазами.

### ⛔ Машинные проверки (обязательные, код 2 = стоп)
1. **Русский черновик, ДО перевода:** `check_text.py <черновик.txt> --ru --hero die` — чужой род рождается в русском («зелёная ручка» = der Stift).
2. **Страница героя:** `check_text.py <страница>` — род (авто из woerter.js; содержательные ❌/структурные ⚠️), линза, объём, покрытие `--require`. Для глагольного блока добавить `--verbblock` (линзу не проверять) и `--part` (норма ~100 слов/часть) — без нужных флагов чекер ругается зря, и ему перестают верить.
3. **Перед деплоем:** `check_pages.py` — робот `speak()` на страницах героев, кавычки/переменные в onclick, рассинхрон перевода DE↔RU, пропуски-из-текста, анти-кэш `?v=N`.

### ⚙️ Глагольные блоки (Отто/Грета/Тео)
- **Формы — только движком** `tools/verben_engine.py` (через генераторы `gen_trennbar.py`/`gen_untrennbar.py`), руками не писать (были findst, bietst, behaltest…). Генераторы и данные — в `tools/`+`data/`, НЕ в scratchpad (стирается; движок уже терялся).
- **Порядок части: ЗНАКОМСТВО → ТЕКСТ → ТРЕНИРОВКА.** Значение до механики; значения неотделяемых — через ОБРАЗ-МОСТ (приставка+корень → сценка + рус. идиома). Упражнения = ПРОГРЕССИЯ-лестница (docs/12), не меню: выбор — разминка, дальше сборка из блоков; письмо пользователю не нравится. Порядок строк всегда перемешивать (иначе учится позиция). Перенося упражнение на нового героя — сначала посчитать на ЕГО данных по частям (пустая группа = не переносить; эталон ≠ шаблон).
- **Тренировать обязательно НА СЛУХ и Perfekt** (подробно docs/12, эталон docs/18). Предложения упражнений — НЕ из текста части и по одному пропуску на предложение (иначе подсказывают друг друга — ловит check_pages).
- **🔁 SRS сквозной:** каждый блок питает общий пул повторения (журнал ошибок, js/ai.js); слова возвращаются по графику забывания ЧЕРЕЗ темы; из журнала — ИИ-мнемоника.
- **Общий словарь глаголов A1+A2** (правильные/неправильные × отделяемые/неотделяемые) — пополнять с каждой темой.

### 🔊 Озвучка
- Только **записанный голос героя** (playWord/playSeq, mp3 edge-tts): der→Killian, die→Katja, das→детский. Браузерный `speak()` (робот) на страницах героев ЗАПРЕЩЁН — и для слов, и для ТЕКСТОВ.
- **При ошибке озвучивать ВЕРНЫЙ ответ** (важнее, чем подтверждать известное); ошибочное возвращать в очередь.
- Правишь немецкий текст → в ту же правку: перевод textRU (источник — страница) и перегенерация mp3 (иначе аудио-рассинхрон, дневник 24.06).

### 📚 Лексика и словарь
- Словарь темы = **ПОЛНЫЙ Lernwortschatz** её уроков (для A2 — рендер сканов + вычитка глазами), разнесённый по роду на героев. Состав не выдумывать — сверять с учебником, показывать пользователю. Уровень «только пройденное» действует на ВСЁ: тексты, упражнения, пропуски, варианты, промпты — и на РУССКИЙ черновик тоже.

### 🖥 Интерфейс и код
- **НЕ вставлять строки/кавычки/JSON и переменные-const в HTML-атрибуты** (onclick) — рвёт атрибут или падает молча; только вызов функции с индексом, данные в JS. Клик проверять реально.
- **UI после правки:** ничего не перекрыто/не обрезано, всё видно; проверять десктоп И телефон.
- **🔑 Согласованность:** изменил принцип в одном месте → примени во ВСЕХ (значки, озвучка по роду, слова сцены=темы, техтексты). Техническими надписями пользователя не грузить (это для разработчика).
- Ссылку после деплоя давать с анти-кэшем (`?nocache=N`), меняя N.
- Перед правкой — читать `docs/03-error-log.md`; после — дописывать.

### 🔀 Параллельные чаты и «одно место»
- Над проектом работают **несколько чатов одновременно**. Перед правкой — `git status`; если файл менялся или есть чужие незакоммиченные правки — **НЕ затирать**: перечитать и вписать поверх, при конфликте сказать пользователю. Законченный кусок — **сразу коммитить** (иначе теряется/конфликтует).
- **Один текст = одно место.** Редактировать СУЩЕСТВУЮЩИЙ слот сцены (напр. «Сцена 2b — офис»), а НЕ добавлять ещё один блок внизу страницы. Дубли внизу = ошибка.

### 👁 Результат пользователь видит на ЖИВОМ сайте
Локальная правка **не видна** — показ требует деплоя: `git push origin main` → `git subtree push --prefix=site origin gh-pages`, потом ссылка с анти-кэшем. Сайт: https://kissheaven9.github.io/Deutsch/ · `materials/` НЕ публиковать.

## Как работаем (договорённость, пользователь — не программист)
- **Технические/внутренние решения принимаю сам, не спрашивая:** код, файлы, структура, библиотеки, где что лежит, как назвать. Пользователь это не оценивает — спрашивать бессмысленно.
- **Спрашиваю ТОЛЬКО то, что пользователь реально может оценить, и коротко по-русски:**
  - контент: тексты-истории, слова, переводы (правило: сначала русский на утверждение);
  - вид/поведение продукта, где есть вкус/мнение;
  - **необратимое или внешнее** (удалить, опубликовать наружу, потратить деньги).
- **Когда спрашиваю — даю рекомендацию и безопасный дефолт**, чтобы «да» = разумный вариант.
- **Безопасность вместо вопросов:** всё под git, любую правку можно откатить. На техническое — «да по умолчанию».
- **Красные линии:** не удалять и не ломать чужие файлы (учебники в materials/, данные) без явного спроса; перед перезаписью — коммит, чтобы был откат.
- **Следовать структуре пользователя, не выдумывать.** Пользователь продумала устройство продукта. Перед разработкой — ЧИТАТЬ документацию (особенно `docs/07-site-structure.md`, `docs/08-tz-otto.md`) и строить ПО НЕЙ. Любое новое описание структуры от пользователя — СРАЗУ фиксировать в документацию, чтобы не переспрашивать и не делать наобум. Если пользователь повторяет — значит, не зафиксировано или не прочитано.

## Порядок работы по задаче (главное правило)
**После того как задача поставлена — работаю до результата сам, не дёргаю пользователя по ходу.** Не прошу подтверждений на каждый шаг, не спрашиваю «можно?» на бытовые решения внутри задачи.
- **Бытовой процесс внутри задачи делаю сам** (как реализовать, какие файлы, порядок шагов, мелкие правки по ходу) — это часть работы, а не повод для вопроса.
- **Закончил — пишу пользователю «готово, проверь»** и коротко: что сделал, что именно посмотреть.
- **Вопрос задаю только когда он реально нужен**, а не «для галочки»:
  - **не уверен** (грамматика, факт, два равнозначных пути, риск сломать) → спрашиваю до того, как делать;
  - **необратимое/внешнее** (удалить чужое, опубликовать наружу, потратить деньги) → спрашиваю всегда;
  - **новый контент** (тексты-истории, слова, переводы) → сначала русский на утверждение (это не «постоянное подтверждение», а единичная сверка смысла).
- **Постоянных подтверждений по ходу — нет.** Если сомнения нет и это не из списка выше — делаю и показываю результат.
- Если вопрос всё же нужен — задаю его сразу и по-русски, с рекомендацией и безопасным дефолтом, чтобы «да» = разумный вариант.
- **Взял задачу — довожу до КОНЦА.** Не отдавать наполовину, не терять пункты сумбурного сообщения; запутался — спросить коротко, а не бросить.
- **Всё, что пользователю не нравится, — СРАЗУ в `docs/03` обобщённо (правилом)**, чтобы не повторять одно и то же по 50 раз. Пользователь повторяет → значит, не зафиксировано.
- **«Готово» =** прошло стоп-лист машинных проверок (код 0) + покрытие слов N/N и фраз + UI сверен (десктоп+телефон) + при необходимости задеплоено и дана ссылка.

## Соответствие тема ↔ уроки (ВАЖНО, частая путаница)
**Тема ≠ один урок.** Тема — это **смысловая группа соседних уроков Momente, СТРОГО по порядку** (без перескоков). **Источник истины по разбивке — `docs/15-wort-thema-karte.md`** (карта «урок → тема» по всем 24 урокам, без дыр и задвоений):
- **Тема 1** = L1–L3 (Знакомство, семья, анкета — контактные поля из L4/L6 тоже сюда) · **Тема 2** = L4–L5 (Быт/дом) · **Тема 3** = **L6 (Офис/работа)** — следующая по плану, пока НЕ собрана · **Тема 4** = L7–L8 (Свободное время).
- ⚠️ На сайте сейчас «Тема 3 = Свободное время (L7)» — это **преждевременный перескок** через непройденный Офис (L6); подлежит переслотке в Тему 4. Сначала собрать Офис (L6).
- **Тема 20** = Lektion 20 (особая тема **по глаголам**: Perfekt/приставки) — номер совпал с уроком, это исключение.
- ❌ Старая формулировка «Тема N = Lektion N» — **неверна** (верна только для Темы 20). Не использовать.
