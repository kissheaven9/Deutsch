# CLAUDE.md — операционная памятка

> Читать в начале каждой сессии. Это приоритетные правила, важнее поведения по умолчанию.

## Приоритет
**Критичность > скорость > простота.** Медленно и верно лучше, чем быстро с ошибкой. Всё проверять перед выдачей. Быть дотошным.

## Жёсткие ограничители (guardrails)
- Любое число — пересчитывать перед выдачей. Итоги должны сходиться.
- Факты — со ссылкой. Неподтверждённое помечать как непроверенное, не выдавать за факт.
- Не выдумывать названия/ссылки/контакты/цифры → писать «не найдено / нужно уточнить».
- Неуверенность помечать явно.
- Видишь ошибку/слабое место → **предлагай решение (одно или несколько), будь аналитичным.** Требовательность без голого критиканства.
- Спорное — оспаривать аргументами, даже если идея пользователя.
- Немецкая грамматика (род, формы, прошедшее время) — проверять, неуверенное помечать.
- **🔴 ГЛАВНОЕ ПРАВИЛО РОДА (ядро всего метода, чек №1 перед выдачей ЛЮБОГО текста):** в тексте героя — **только его род**. der → Otto, die → Грета, das → Тео. Любое содержательное существительное (природа, животные, предметы, категория) ДОЛЖНО быть рода героя; чужой род — убрать или **отдать тому герою, чей это род** (die Wiese/Gegend → Грета, das Schaf → Тео, der Fluss → Otto). Проверка не на память: **прогнать `tools/check_text.py <страница>`** (код 2 = не выдавать). Он берёт род АВТОМАТИЧЕСКИ из `site/js/woerter.js`, ловит чужой род (содержательные ❌ / структурные ⚠️), проверяет **чистоту линзы** (цена→Отто, цвет→Грета, материал→Тео — признак это ключ извлечения, см. docs/17 §0), объём и покрытие (`--require "Wort1,Wort2"`). Выдавать только при 0 чужеродных содержательных. Работает на всех форматах страниц. ⚠️ Машина НЕ проверит «прожито или названо» — тесты docs/17 §0б (вычёркивания/анонимности/«ну и что?») прогонять самому. Нарушал многократно (дневник №18, 29.06) — поэтому проверка обязательная и автоматическая, а не «на глаз».
- **⚙️ Формы глаголов — только генератором** (`tools/gen_trennbar.py`), руками не писать: были ошибки findst/findt, bietst, kreuzst, ladt, arbeitt. Генераторы держать в `tools/`, не в scratchpad (стирается).
- **📚 Словарь темы = ПОЛНЫЙ Lernwortschatz её уроков, не выборка «по памяти».** Брать ВСЕ слова уроков из учебника (для A2 — рендер сканов Lernwortschatz + вычитка глазами, текстового слоя нет), разнести по роду на трёх героев. Не выдумывать состав (животные/страны/природа) — сверять с учебником и показывать пользователю.
- **🔁 Обновлять ОБЩИЙ СЛОВАРЬ ГЛАГОЛОВ с каждой темой.** Есть единый словарь глаголов по всему A1+A2, сгруппированный **правильные/неправильные × отделяемые/неотделяемые**. Новые глаголы темы СРАЗУ вносить туда (и в тренажёр), иначе он устаревает. Тренировка глаголов — обязательно НА СЛУХ (приставка уходит в конец плохо слышна): выцепи-глагол → услышь-и-переведи → вставь-в-форме → Perfekt → тест-аудирование (история + вопросы на понимание действия). Подробно — docs/12 «Аудирование глаголов».
- **⚠️ НЕ вставлять строки с кавычками/JSON в HTML-атрибуты** (onclick и пр.) — рвёт атрибут, кнопка мертва (дневник 01.07). Только индексы/идентификаторы; данные — в JS, брать по индексу. Клик проверять реально.
- **Перед написанием/выдачей учебного текста — работать по `docs/17-text-anleitung.md`** (единая пошаговая инструкция «как написать идеальный текст»). Кратко: прочитать docs/10–12 + свежие docs/03 + bible героя + Lernwortschatz урока → писать длинно (16–20 строк) через ЛИНЗУ героя историей (не списком), все слова рода И все фразы урока (приветствие+прощание), уровень по уроку, спираль 30/70 → прогнать ЧЕК-ЛИСТ с ТАБЛИЦЕЙ ПОКРЫТИЯ (слова N/N, фразы) ДВАЖДЫ → показывать ТОЛЬКО после проверки, приложив итог покрытия. Не повторять прошлые ошибки (мёртвый список, чужой род, короткий текст, неполная лексика/фразы).
- Любой материал/копирайт → сначала по-русски на утверждение, перевод на немецкий только после «ок».
- Общение — по-русски.
- **UI-вёрстка:** после любой правки интерфейса проверять, что **ничего не перекрывает друг друга, не обрезано и помещается** — все слова, буквы, кнопки, стрелки видны. Частая ошибка; не выдавать, пока не сверил. **Проверять и десктоп, и телефон.**
- **🔑 ГЛАВНОЕ ПРАВИЛО СОГЛАСОВАННОСТИ:** меняешь принцип/решение в одном месте — распространяй на ВСЕ остальные. Примеры: значки ✅/⚠️ у глаголов — везде (словарь, разделы, темы); озвучка по роду (der→Otto, die→Грета, das→Тео) — во всех разделах; слова сцены = слова темы; убрал техтекст — убери везде. После такой правки пройтись по всем страницам и применить единообразно.
- **Технические надписи не показывать пользователю** («структура темы…», «лексика сверена по Lernwortschatz», «данные в js/…», «Perfekt — ориентир» и т.п.) — это для разработчика, на пользовательских страницах не выводить.
- Перед правкой — сверяться с `docs/03-error-log.md`; после — дописывать.

## Как работаем (договорённость, пользователь — не программист)
- **Технические/внутренние решения принимаю сам, не спрашивая:** код, файлы, структура, библиотеки, где что лежит, как назвать. Пользователь это не оценивает — спрашивать бессмысленно.
- **Спрашиваю ТОЛЬКО то, что пользователь реально может оценить, и коротко по-русски:**
  - контент: тексты-истории, слова, переводы (правило: сначала русский на утверждение);
  - вид/поведение продукта, где есть вкус/мнение;
  - **необратимое или внешнее** (удалить, опубликовать наружу, потратить деньги).
- **Когда спрашиваю — даю рекомендацию и безопасный дефолт**, чтобы «да» = разумный вариант.
- **Безопасность вместо вопросов:** всё под git, любую правку можно откатить. На техническое — «да по умолчанию».
- **Красные линии:** не удалять и не ломать чужие файлы (учебники в materials/, данные) без явного спроса; перед перезаписью — коммит, чтобы был откат.
- **Следовать структуре пользователя, не выдумывать.** Пользователь продумала устройство продукта. Перед разработкой — ЧИТАТЬ документацию (особенно `docs/07-site-structure.md`, `docs/08-tz-otto.md`) и строить ПО НЕЙ. Любое новое описание структуры от пользователя — СРАЗУ фиксировать в документацию, чтобы не переспрашивать и не делать наобум. Если пользователь повторяет — значит, не зафиксировано или не прочитано.

## Порядок работы по задаче (главное правило)
**После того как задача поставлена — работаю до результата сам, не дёргаю пользователя по ходу.** Не прошу подтверждений на каждый шаг, не спрашиваю «можно?» на бытовые решения внутри задачи.
- **Бытовой процесс внутри задачи делаю сам** (как реализовать, какие файлы, порядок шагов, мелкие правки по ходу) — это часть работы, а не повод для вопроса.
- **Закончил — пишу пользователю «готово, проверь»** и коротко: что сделал, что именно посмотреть.
- **Вопрос задаю только когда он реально нужен**, а не «для галочки»:
  - **не уверен** (грамматика, факт, два равнозначных пути, риск сломать) → спрашиваю до того, как делать;
  - **необратимое/внешнее** (удалить чужое, опубликовать наружу, потратить деньги) → спрашиваю всегда;
  - **новый контент** (тексты-истории, слова, переводы) → сначала русский на утверждение (это не «постоянное подтверждение», а единичная сверка смысла).
- **Постоянных подтверждений по ходу — нет.** Если сомнения нет и это не из списка выше — делаю и показываю результат.
- Если вопрос всё же нужен — задаю его сразу и по-русски, с рекомендацией и безопасным дефолтом, чтобы «да» = разумный вариант.

## Соответствие тема ↔ уроки (ВАЖНО, частая путаница)
**Тема ≠ один урок.** Тема — это **смысловая группа соседних уроков Momente, СТРОГО по порядку** (без перескоков). **Источник истины по разбивке — `docs/15-wort-thema-karte.md`** (карта «урок → тема» по всем 24 урокам, без дыр и задвоений):
- **Тема 1** = L1–L3 (Знакомство, семья, анкета — контактные поля из L4/L6 тоже сюда) · **Тема 2** = L4–L5 (Быт/дом) · **Тема 3** = **L6 (Офис/работа)** — следующая по плану, пока НЕ собрана · **Тема 4** = L7–L8 (Свободное время).
- ⚠️ На сайте сейчас «Тема 3 = Свободное время (L7)» — это **преждевременный перескок** через непройденный Офис (L6); подлежит переслотке в Тему 4. Сначала собрать Офис (L6).
- **Тема 20** = Lektion 20 (особая тема **по глаголам**: Perfekt/приставки) — номер совпал с уроком, это исключение.
- ❌ Старая формулировка «Тема N = Lektion N» — **неверна** (верна только для Темы 20). Не использовать.
